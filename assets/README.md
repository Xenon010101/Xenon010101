# Profile artwork

Original, self-contained SVG artwork for Anmol Patel's GitHub profile. Both themes include dedicated desktop and mobile compositions. The profile works without running any code or fetching fonts, badges, or live statistics.

To edit the artwork, change `generate.py`, then run from the repository root:

```sh
python assets/generate.py
```

Python 3.6 or newer is sufficient; no packages are required. The generator replaces only the SVG files it owns in this directory. Commit the generated SVGs with the root README. It does not modify the contribution-snake workflow or its output branch.

Colors are defined in `PALETTES`. The `hero`, `card`, `achievement`, and `footer` functions control each composition. Update corresponding alt text and readable copy in the root README when changing content. Achievement wording comes from the original README; update it only with confirmed information.

The project illustrations are conceptual artwork, not screenshots or measured results. The optional contribution snake is the only generated remote image in the profile.

## Contribution activity

`activity.json` and the four `activity-*.svg` cards are real snapshots, generated by `update_activity.py`. This script requires Python 3.7 or newer. The standard artwork generator leaves them untouched. To restyle a saved snapshot without making a network request:

```sh
python assets/update_activity.py --offline
```

The **Refresh profile activity** workflow fetches GitHub's GraphQL API daily at 03:23 UTC, on relevant pushes to `main`, and through **Actions → Refresh profile activity → Run workflow**. It uses the built-in `GITHUB_TOKEN`; no personal access token or external card service is needed. Upload the workflow along with the README and assets to enable automatic refreshes.

The card shows GitHub's past-year contribution window, pull requests opened, and pull-request reviews. Weekly bars sum the API's daily contribution counts; they are real activity data. These are contribution counts, not a claim about code quality or merged pull requests. The exact range and snapshot date are saved in the JSON and shown beside the card. GitHub's calendar can include partial boundary weeks. Counts reflect the data visible to the API token.

Each successful refresh commits only the activity snapshot, its four cards, and the generated block between the root README's `ACTIVITY:START` and `ACTIVITY:END` markers. Leave these markers in place. A failed request or invalid response stops the workflow before its commit step, preserving the last published files. A rejected push also leaves the published snapshot intact. If refreshes stop, run the workflow manually and check its logs; the image files remain available.

The initial snapshot was fetched from GitHub on 2026-09-10. Refreshing locally requires a GitHub token in `GH_TOKEN` or `GITHUB_TOKEN`; the script never saves or prints it. For offline validation, run `python -m unittest discover -s .github/tests`.
